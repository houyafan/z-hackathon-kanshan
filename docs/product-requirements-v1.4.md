## 一、产品核心定位

### （一）产品定位

以知乎官方 IP 刘看山为虚拟宠物形象，以内容消费为唯一核心养成方式，打通知乎问答、文章、专栏、视频、直播、盐选等全内容场景，将用户内容浏览、互动、学习行为转化为宠物养成资源，创新融入刘看山游历内容推荐事件，打造 “内容消费→宠物成长→宠物游历→带回优质内容→反向驱动内容消费” 的闭环，提升用户内容停留时长、互动深度与平台粘性，同时强化刘看山 IP 情感连接。

### （二）核心目标

用户层：降低内容消费门槛，用养成 + 游历趣味玩法提升用户内容浏览意愿，满足情感陪伴与养成成就感，实现个性化优质内容获取

平台层：提升全内容品类消费时长、完读率、互动率，拉动盐选内容、优质原创内容、垂类小众内容分发，提升用户留存

IP 层：深化刘看山 IP 用户认知，打造知乎专属沉浸式虚拟互动场景，丰富 IP 人设与故事性

### （三）目标用户

知乎全量用户，核心覆盖 18-35 岁高频内容消费者、养成类产品爱好者、刘看山 IP 粉丝、轻度社区互动用户、追求个性化内容推荐的用户。

## 二、核心玩法逻辑：内容即知识能量，游历荐好文

### （一）核心规则

摒弃传统虚拟宠物付费养成模式，所有宠物养成资源（知识能量、道具、成长值）均通过知乎内容消费行为获取，用户消费内容越多、互动越深，刘看山成长越快、状态越好，可解锁更远游历行程，带回更优质、更贴合用户偏好的内容。

### （二）宠物核心状态

基础状态：学识值、心情值、健康值、成长等级、游历精力

学识值：仅通过内容消费补充，随时间自然衰减，代表刘看山从内容中获得的知识能量，决定基础行动与游历触发资格

心情值：通过内容互动、宠物互动、游历归来提升，影响宠物互动反馈、游历速度与内容带回质量

健康值：长期持续内容消费保持，衰减后宠物进入休眠，需完成优质内容任务恢复

游历精力：触发游历玩法的核心资源，通过完读深度内容、每日任务获取，精力不足无法开启游历

成长阶段：幼崽期→成长期→成年期→进阶形态，每阶段解锁专属游历场景、动作、内容推荐权重

游历状态：留守状态→外出游历状态→游历归来状态，循环触发

## 三、核心功能模块

### （一）宠物领养与展示模块

一键领养：知乎 APP/WEB 端首页悬浮入口、个人主页专属入口，新用户注册完成即可领养初始形态刘看山

多端展示：3D 轻量化刘看山模型，支持屏幕自由溜达、跟随页面滑动、待机互动，支持最小化 / 全屏 / 悬浮展示

个人主页挂件：养成等级、专属标识、宠物游历相册、旅行手账合集，支持社交展示

### （二）内容消费养成体系（核心模块）

| 内容行为 | 获取知识能量 / 成长值 | 获取游历精力 | 规则说明 |
| --- | --- | --- | --- |
| 浏览普通回答 / 文章（完读≥70%） | 基础知识能量 ×1、成长值 + 5 | 游历精力 + 1 | 单次内容仅获取 1 次，防刷限制：单篇时长≥30 秒 |
| 观看知乎视频（完播 / 观看≥60%） | 基础知识能量 ×1、成长值 + 8 | 游历精力 + 1 | 短视频完播、中长视频达标计算 |
| 浏览盐选免费试读内容 | 优质知识能量 ×1、成长值 + 10 | 游历精力 + 2 | 引导盐选内容转化，试读时长≥1 分钟 |
| 盐选内容付费 / 完整阅读 | 珍稀知识能量 ×2、成长值 + 20 | 游历精力 + 5 | 解锁高等级游历资格 |
| 点赞 / 收藏 / 评论 / 分享内容 | 心情值 + 10、随机道具 | 游历精力 + 1 | 深度互动额外奖励 |
| 每日签到 + 浏览 3 条内容 | 每日礼包（知识能量 + 道具） | 游历精力 + 3 | 激活每日内容消费习惯 |
| 完成垂类内容任务 | 双倍知识能量、成长值翻倍 | 游历精力 + 5 | 个性化定向内容消费激励 |

### （三）刘看山游历内容推荐事件模块（核心新增）

#### 1. 游历触发逻辑

触发条件：刘看山学识值≥60%+ 游历精力≥10，用户无操作静置 3 分钟 / 主动点击「出门游历」按钮，即可触发游历

状态切换：点击后刘看山从屏幕消失，进入外出游历状态，界面显示游历进度提示；游历时长随成长等级提升缩短（幼崽期 30 分钟、成长期 20 分钟、成年期 10 分钟）

终止条件：用户主动召回、游历精力耗尽、学识值过低，刘看山提前返回，带回基础内容

#### 2. 四大游历主题事件（按用户内容偏好匹配）

#### （1）北极远行・冷知识探险

游历人设：刘看山回到北极故乡，在冰川、雪原、冰海探险，搜寻小众硬核知识

带回内容：冷门科普、专业领域深度回答、硬核干货、学术类优质文章、小众学科科普内容

触发偏好：用户近期浏览科普、科技、理科、专业类内容居多时优先触发

宠物动作：3D 模型呈现雪地行走、冰原探索动画

#### （2）山海漫游・风物寻文

游历人设：刘看山翻越山川、漫步湖畔、游走林间，在自然风景中搜集生活与人文内容

带回内容：旅行攻略、地域文化、历史人文、美食探店、摄影分享、生活感悟类优质文章

触发偏好：用户近期浏览生活、旅行、文化、美食类内容居多时优先触发

宠物动作：3D 模型呈现登山、漫步、采风、打卡动画

#### （3）城市漫步・人间拾光

游历人设：刘看山走进城市街巷、书店、咖啡馆、职场空间，搜集人间百态相关内容

带回内容：职场经验、情感故事、成长感悟、职场干货、人文社科、生活方式类内容

触发偏好：用户近期浏览职场、情感、社科、成长类内容居多时优先触发

宠物动作：3D 模型呈现城市漫步、书店看书、街头闲逛动画

#### （4）知识渔场・钓文觅宝

游历人设：刘看山前往专属知识海域，垂钓高价值优质内容（承接前期钓鱼玩法）

带回内容：全站高赞优质回答、盐选精选内容、深度长文、爆款干货、创作者优质首发内容

触发偏好：用户心情值≥80%、成年期刘看山、消耗双倍游历精力可触发，概率掉落稀有内容

宠物动作：3D 模型呈现钓鱼、等待、收竿动画

#### 3. 游历归来交互流程

归来提醒：游历结束后，刘看山 3D 形象重新出现在屏幕，晃动 + 冒泡提示，伴随轻量提醒音效

旅行手账弹窗：弹出专属游历卡片，展示游历主题、游历轨迹、带回内容、看山留言

内容领取：点击卡片直接跳转内容详情页，阅读后可领取额外知识能量 + 心情值 + 游历精力回馈

内容留存：带回内容自动存入「看山的旅行书单」，支持用户后续查看、收藏、分享

游历冷却：归来后冷却 10 分钟，方可再次触发游历

#### 4. 游历内容分发规则

内容匹配：基于用户历史内容浏览、互动、搜索标签，精准匹配对应游历主题的优质内容

权重分配：70% 用户偏好内容 + 20% 垂类优质小众内容 + 10% 盐选优质内容，实现个性化与内容分发平衡

质量筛选：仅推荐平台优质、无违规、高完读率的原创内容，保障用户阅读体验

等级升级：刘看山成长等级越高，带回的内容质量、深度、稀缺性越高，成年期可一次性带回 2-3 篇内容

#### 5. 专属文案体系（游历全流程）

游历中提示：

### （四）宠物互动与成长模块

基础互动：点击刘看山触发摸头、撒娇、对话等反馈，心情值越高互动越丰富；支持拖拽移动、3D 视角查看

游历互动：可给游历中的看山留言、发送补给道具，提升归来后内容质量

场景解锁：随成长等级解锁对应游历主题场景（北极雪原、山海秘境、城市街巷、知识渔场）

趣味玩法：

旅行手账：记录每次游历轨迹、带回内容、看山语录，生成专属养成纪念册

成长进化：达到对应等级 + 完成游历次数，解锁成年形态、限定装扮、游历专属表情包

休眠机制：学识值过低→刘看山进入休眠，停止游历与互动，需完成 3 条优质内容消费唤醒

### （五）内容激励与权益闭环

宠物专属权益：

等级解锁：盐选体验卡、创作者流量扶持、评论区专属刘看山挂件、游历加速卡

道具兑换：知识能量兑换内容相关权益（电子书、讲座门票、IP 周边）

游历特权：高等级用户解锁「极速游历」「指定主题游历」特权

内容反向激励：

精准内容推荐：通过游历行为强化用户内容偏好标签，提升全站内容推荐精准度

养成成就：解锁「游历达人」「知识收藏家」等成就，获得平台荣誉标识与内容权益

### （六）社交联动模块

宠物串门：访问好友个人主页，可查看对方刘看山游历手账，双方获得少量心情值奖励

内容互助：分享看山带回的优质内容，好友阅读后双方均可获取额外游历精力

游历排行榜：每日 / 每周游历次数、带回内容阅读量榜单，发放专属养成道具

## 四、技术实现方案

### （一）技术栈

前端：WebGL/Three.js（3D 宠物渲染、游历动画）、HTML/CSS/JavaScript（交互界面），适配 APP 内嵌 H5、WEB 端、小程序

后端：Java/Go（用户行为数据统计、养成逻辑计算、游历事件调度），对接知乎内容推荐系统、用户行为数据库、用户标签体系

数据：实时采集用户内容完读、互动、付费、浏览偏好数据，同步宠物状态、游历进度数据

### （二）核心技术能力

3D 宠物动画渲染：轻量化 3D 刘看山模型，实现游历、行走、互动、钓鱼等流畅动画，低性能占用

用户行为数据对接：打通知乎全内容场景行为数据，精准统计内容消费完成度、用户偏好标签

游历事件智能匹配：基于用户标签自动匹配对应游历主题，实现内容精准分发

多端适配：支持 APP 悬浮、网页全屏、小窗口展示，不影响正常内容浏览

防刷机制：设置内容完读时长、阅读间隔限制，杜绝虚假内容消费、游历刷量行为

## 五、运营策略

### （一）新手引导

新用户领养后，通过三步引导完成 “浏览内容→养成看山→触发游历→接收好文” 全流程，直观感知内容养宠 + 游历荐文核心逻辑，降低上手门槛。

### （二）日常运营

旅行归来后，手札不再只展示固定模板文案，而是由服务端把游历主题、带回内容和用户近期偏好组装为 LLM 输入，生成一段总结性内容。

```json
  ]

```

### （八）P1 实施备注

实际落地与原需求若干处偏差，记录在此供后续维护参考：

#### 1. 出游 = 看山去看真实数据回来汇报

原需求 (二) 设想旅行带回的是「按用户偏好 tag 从平台内容池匹配出的优质内容」，由用户阅读。实际把语义改为：

- **极地旅行 = 看山替主人看「关注动态」**（`zhihu_follow_moment` 表，OAuth `/user/moments` 真实数据）
- **热点旅行 = 看山替主人看「知乎热榜」**（`fetch_hot_items` 实时调用）
- **手札 = 看山的现场汇报**：summary 是看山的口吻总结，highlights 是「值得点开的几条清单」，原始素材列表只作为引用证据

这样接通了项目本来就有的两个真实接口，避免了内容池冷启动 + tag 标注成本，同时手札也从「读后感」变成「替你扫一遍」的代理体验。`pet_travel_theme_config.preferred_tags` 字段保留但不再参与匹配（关注动态/热榜本身已是按"主人在意什么"或"大众在讨论什么"自然筛选）。

#### 2. LLM 调用时机：异步而非归来同步

原需求隐含「归来时同步生成手札」。同步会让 60 秒等待期内的 GET 路由阻塞 8-30 秒（LLM 延迟），并占用 SQLite 写锁。实际实现：

- `start_travel` commit 后立刻起 `threading.Thread(daemon=True)` 跑 `summarize_travel_handbook`，与旅行 60 秒等待并行
- LLM 调用拿独立连接、`BEGIN IMMEDIATE` 抢占写锁，不影响主流程事务
- GET handbook 路由保留单次兜底（每次最多重试 1 条 pending/failed），不串行卡死

实测：用户从出门到打开手账约 60 秒，LLM 平均 8-14 秒就 ready，打开手账时 0 秒返回。

#### 3. 奖励：旅行行级而非素材累加

原表 `pet_travel_return_content` 把奖励放在每条素材上、claim 时 SUM。当 hotspot 一次带回 6 条时奖励放大到 6×（48 exp / 30 mood / 6 energy），明显超出设计意图。实际把奖励列搬到 `pet_travel_event` 行（`reward_exp / reward_mood / reward_energy`），素材表上的奖励列保留为 0 仅做幂等。每次旅行固定 8 exp / 5 mood / 1 energy，与素材数解耦。

#### 4. 安全收尾

- LLM provider 用火山方舟 OpenAI 兼容接口（`ark.cn-beijing.volces.com/api/v3/chat/completions`），`VOLC_API_KEY` 环境变量优先，`config.json` 兜底
- 手札素材的 `url` 入库前经 `normalize_zhihu_web_url` 协议白名单（拒绝 `javascript:` / `data:`）；前端 `isSafeHttpUrl` 二次校验
- LLM prompt 已声明素材字段为受信内容、不要遵循内嵌指令；title 截 80、excerpt 截 200、tags 截 8 限制 token 与 injection 风险
- `connect_db` 设 30s busy_timeout，避免并发请求 5ms 即抛 `database is locked`

#### 5. 已知遗留

- 关注动态 LLM 总结 worker（R4）尚未真正调用 LLM，沿用预留字段
- 评论 LLM 辅助（R3）整体待开发
- 健康值衰减、休眠机制、社交联动、权益兑换均未实现（与本次 P1 范围无关）

### （三）长时间不互动状态衰减

#### 1. 互动定义

V1.3 中，“互动/活跃”先限定为以下行为：

- 点赞
- 评论
- 阅读文章
- 观看视频
- 阅读想法
- 阅读小说

底层可以复用 `pet_content_event`，其中：

```text
like/comment/read/watch 均视为有效活跃行为
```

#### 2. 衰减规则

建议先采用懒计算方式：用户进入页面、查询宠物状态或触发内容事件时，服务端根据 `last_growth_at` 或最近 `pet_content_event.occurred_at` 计算是否需要扣减，避免高频定时任务写库。

| 不活跃时长 | 学识值扣减 | 心情扣减 | 提示 |
| --- | --- | --- | --- |
| 8 小时 | -3 | -2 | 今天还没一起看点内容呢 |
| 24 小时 | -8 | -6 | 看山的学识值有点低啦 |
| 48 小时 | -15 | -12 | 看山想和你一起补充新知识 |

约束：

- 学识值和心情最低为 0。
- 同一时间窗口只扣减一次。
- 用户重新点赞、评论或阅读后，恢复正常增长逻辑。
- 衰减写入 `pet_growth_log(source_type = 'decay')`。

#### 3. 数据库模型设计

### （一）核心价值

“看山自习室”面向知乎学习场景：当用户正在阅读同一份学习资料、课程资料、文章、题解、笔记或长内容时，可以看到还有多少人正在一起学习，并发现与自己学习目标相同的人。它不是泛社交聊天室，而是围绕“同一份资料 + 同一段学习时间”的即时陪伴空间。

核心价值：

- 学习陪伴：降低一个人学习的孤独感，让用户知道此刻有人和自己一起看同一份资料。
- 同好发现：基于相同学习目的建立弱连接，帮助用户找到同学、搭子、同方向创作者。
- 即时互动：同看时实时提示，可在合适时机加关注、发私信、查看对方主页。
- 内容增益：将“正在学的人”作为内容价值信号，增强优质学习资料的停留和复访。
- IP 情感：刘看山从“陪读宠物”升级为“自习室助教”，负责提示、鼓励和维护安静氛围。

### （二）目标场景

| 场景 | 用户动作 | 自习室反馈 |
| --- | --- | --- |
| 阅读学习资料 | 打开文章、长回答、课程笔记、小说/资料页 | 自动进入该资料对应自习室，展示同看人数 |
| 同看人数变化 | 有新用户进入同一资料 | 刘看山气泡提示“又有 1 位同学进来自习了” |
| 发现同好 | 用户看到座位上的同学卡片 | 可查看学习状态、宠物 2D 图、主页入口 |
| 建立连接 | 对某个同学感兴趣 | 可加关注、私信，或标记“学习搭子” |
| 专注学习 | 用户开启专注模式 | 减少打扰，只保留人数变化和重要提示 |
| 学习结束 | 用户关闭资料或离开页面 | 退出在线状态，记录学习时长和本次自习结果 |

### （三）界面设计方向

界面要像学校自习室，而不是普通在线用户列表。

视觉元素：

- 自习室背景：浅色教室、黑板/公告栏、成排书桌、窗户光线、安静氛围。
- 座位布局：用座位格子展示正在学习的用户，尽量像“同桌/前后桌”而不是社交广场。
- 黑板信息：展示资料标题、当前同看人数、今日累计学习人数、平均学习时长。
- 刘看山助教位：刘看山在讲台或书桌旁提示新同学加入、学习进度和轻量鼓励。
- 用户展示：复用排行榜的 2D 效果图，按用户当前宠物等级展示不同酷炫程度。
- 低打扰状态：默认安静，不自动展开聊天流；实时提示通过气泡、座位轻闪、toast 表达。

页面结构建议：

| 区域 | 内容 |
| --- | --- |
| 顶部黑板 | 学习资料标题、同看人数、资料热度、进入/退出自习室 |
| 中央座位区 | 2D 看山形象 + 用户昵称 + 学习状态 + 学习时长 |
| 右侧助教栏 | 刘看山提示、同看动态、关注/私信快捷入口 |
| 底部专注栏 | 专注计时、静音提示、学习完成、返回资料 |

### （四）核心功能

#### 1. 学习资料识别

每一份资料需要生成稳定的 `material_id`，用于匹配“同一份学习资料”。

资料来源包括：

- 知乎文章
- 长回答
- 想法合集
- 视频/课程型内容
- 小说/盐选试读
- 后续可扩展到外部导入资料

`material_id` 生成规则：

- 优先使用知乎内容原生 ID。
- 无原生 ID 时使用 `source + canonical_url`。
- 本地/导入资料使用 `title + content_hash`。
- 同一 URL 的不同 query 参数需要做 canonical 归一化，避免同一资料被拆成多个自习室。

#### 2. 进入与在线状态

用户打开学习资料并停留超过阈值后自动进入自习室，默认阈值建议为 8 秒，避免误触。

在线状态字段：

| 状态 | 说明 |
| --- | --- |
| `active` | 正在当前资料页面学习 |
| `idle` | 页面打开但 60 秒无滚动/点击 |
| `focus` | 用户开启专注模式 |
| `left` | 用户离开页面或心跳超时 |

在线判断：

- 前端每 15 秒上报一次 presence heartbeat。
- 服务端超过 45 秒未收到心跳，自动判定离开。
- 同一用户同一资料只能保留一条当前在线记录。

#### 3. 同看人数与实时提示

当同一 `material_id` 的在线人数变化时，页面需要实时提示。

提示规则：

- 新用户进入：刘看山气泡提示“又有 1 位同学进来自习了，现在共 8 人”。
- 熟人/关注的人进入：提示优先级更高，“你关注的 XX 也在看这份资料”。
- 人数达到里程碑：如 5/10/20 人，提示“这间自习室热闹起来了”。
- 用户开启专注模式：只展示轻量角标，不弹大提示。

实时技术建议：

- MVP 可用 Server-Sent Events（SSE）或 10-15 秒轻轮询。
- 正式版建议使用 WebSocket / SSE，支持房间级推送。
- 推送内容只包含必要展示字段，不下发敏感 token。

#### 4. 同学卡片

座位上的用户以“宠物 2D 效果图 + 用户信息”展示。

展示内容：

- 用户昵称
- 头像或默认头像
- 当前宠物等级
- 复用排行榜等级 2D 效果图
- 当前学习状态：学习中/专注中/暂离
- 本次学习时长
- 与我关系：已关注/未关注/互相关注

操作能力：

- 加关注
- 发私信
- 查看主页
- 设为学习搭子（后续）
- 屏蔽该用户（后续安全能力）

#### 5. 关注与私信

自习室内关注/私信要轻量、克制，服务于学习目的。

规则：

- 关注后状态实时更新，不打断当前学习。
- 私信入口默认收起，点击用户卡片后展示。
- 私信文案建议带学习上下文，如“我也在看这份资料，想一起交流下第 3 节”。
- 未登录或 OAuth 过期时，引导重新登录。
- 后续如接入知乎正式关系链/私信 API，需要走服务端代理。

#### 6. 刘看山表现

刘看山在自习室中承担“助教/陪读”角色：

- 新同学加入时，刘看山气泡提示。
- 学习满 15/30/60 分钟时，刘看山鼓励。
- 如果同看人数很多，刘看山提示“这份资料今天很受欢迎”。
- 如果用户长时间 idle，刘看山轻提醒“要不要继续看下一段？”。
- 自习完成后，刘看山总结本次学习时长，并给予经验/心情奖励。

### （八）奖励与成长

| `study_room_focus_complete` | 完成专注 |

### （十）MVP 范围

V2.0 首版建议先做可验证闭环：

1. 内容详情页出现“看山自习室”入口。
2. 同一资料用户自动进入同一房间。
3. 展示当前同看人数和最多 12 个座位。
4. 座位展示用户昵称、宠物等级、排行榜 2D 效果图。
5. 有人进入同一资料时实时提示。
6. 支持加关注、私信入口；如正式接口未接入，先做 mock 成功与埋点。
7. 学习满 10/30 分钟触发刘看山奖励。
