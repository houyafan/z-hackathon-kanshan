# 看山陪伴计划｜埋点落地方案

本文基于 `docs/埋点设计开发文档.md`，结合当前项目已实现的 SQLite、OAuth、本地调试、管理后台、内容消费、排行榜、发圈子和成长日志能力，给出可直接拆任务开发的埋点落地方案。

## 1. 当前状态

### 已具备

- 登录与用户体系：`zhihu_user`、`auth_session` 已存在，接口均可从 session 获取可信 `user_id`。
- 内容消费事实：`pet_content_event` 已记录阅读、观看、点赞、评论、收藏等养成事件。
- 成长流水：`pet_growth_log` 已记录经验、等级、学识值、心情、游历精力等奖励与衰减。
- 游历记录：`pet_travel_event` 已支持游历开始、归来、领取。
- 排行榜与分享：已有等级榜、游历榜、发圈子奖励、每日分享频控。
- 管理后台：已有基础后台入口，并已接入 `project_daily_metric` 每日注册/登录折线图。

### 缺口

- 缺少统一埋点事实表，无法完整记录曝光、停留、点击、弹窗、分享等非养成行为。
- 缺少前端会话 ID，难以统计路径、停留时长、页面访问深度。
- 缺少用户日聚合，后台无法直接展示留存、活跃、跳出、分享转化等指标。
- 现有内容、成长、游历数据可复用，但还没有映射成统一指标口径。

## 2. 落地目标

P0 先完成最小闭环：

- 记录首页看山模块曝光、模块停留、页面停留。

- 管理后台展示核心趋势和漏斗：曝光 UV、平均停留、升级 UV、游历 UV、分享点击/成功。
- 支持后续路演可引用的数据口径。

P1 再补齐：

- D1/D3/D7 留存 cohort。
- 分享回流识别。
- 页面路径分析和更细的漏斗。
- 自习室埋点扩展。

## 4. 数据库模型

### 4.1 `analytics_event`

统一事件事实表，写入所有前端和服务端埋点。

```sql
CREATE TABLE IF NOT EXISTS analytics_event (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  event_id TEXT NOT NULL,
  user_id INTEGER,
  session_id TEXT NOT NULL,
  event_name TEXT NOT NULL,
  page_path TEXT,
  referer_path TEXT,
  target_type TEXT,
  target_id TEXT,
  duration_ms INTEGER NOT NULL DEFAULT 0 CHECK (duration_ms >= 0),
  props TEXT NOT NULL DEFAULT '{}',
  client_ts TEXT,
  server_ts TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,

  UNIQUE (event_id)
);

CREATE INDEX IF NOT EXISTS idx_analytics_event_user_time
  ON analytics_event (user_id, server_ts);

CREATE INDEX IF NOT EXISTS idx_analytics_event_session_time
  ON analytics_event (session_id, server_ts);

CREATE INDEX IF NOT EXISTS idx_analytics_event_name_time
  ON analytics_event (event_name, server_ts);

CREATE INDEX IF NOT EXISTS idx_analytics_event_page_time
  ON analytics_event (page_path, server_ts);
```

### 4.2 `analytics_session`

前端会话表，用于计算访问深度、总停留、入口/出口。

```sql
CREATE TABLE IF NOT EXISTS analytics_session (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id TEXT NOT NULL,
  user_id INTEGER,
  started_at TEXT NOT NULL,
  ended_at TEXT,
  duration_ms INTEGER NOT NULL DEFAULT 0 CHECK (duration_ms >= 0),
  entry_path TEXT,
  exit_path TEXT,
  page_view_count INTEGER NOT NULL DEFAULT 0 CHECK (page_view_count >= 0),
  content_open_count INTEGER NOT NULL DEFAULT 0 CHECK (content_open_count >= 0),
  interaction_count INTEGER NOT NULL DEFAULT 0 CHECK (interaction_count >= 0),
  travel_action_count INTEGER NOT NULL DEFAULT 0 CHECK (travel_action_count >= 0),
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,

  UNIQUE (session_id)
);

CREATE INDEX IF NOT EXISTS idx_analytics_session_user_start
  ON analytics_session (user_id, started_at);
```

## 6. 前端采集方案

新增 `p0_mock/static/analytics.js` 或直接在 `app.js` 中先实现轻量模块。

### 6.1 会话 ID

- `sessionStorage.liukanshan_analytics_session_id` 存储前端会话 ID。
- 新标签页新会话，刷新保留。
- 格式：`lks_${Date.now()}_${random}`。

### 6.2 上报策略

- 事件先进入内存队列。
- 普通事件 3 秒或 10 条批量上报一次。
- `page_leave`、`session_end`、`pet_module_stay` 使用 `navigator.sendBeacon` 优先上报。
- 如果 `sendBeacon` 不可用，回退 `fetch(..., { keepalive: true })`。
- `event_id` 客户端生成，服务端 `UNIQUE(event_id)` 去重。

### 6.3 页面停留

在 `renderCurrentRoute()` 前后记录：

- 旧页面：上报 `page_leave`，带 `duration_ms`。
- 新页面：上报 `page_view`。

页面路径按现有路由：

- `/`
- `/people/p2wcex`
- `/follow`
- `/hot`
- `/community`
- `/admin`

### 6.4 看山模块曝光与停留

目标元素：

- `[data-pet-panel]`

实现：

- 使用 `IntersectionObserver`，阈值建议 `0.5`。
- 首次进入视口上报 `pet_module_expose`。
- 每次进入视口记录开始时间，离开视口或页面隐藏上报 `pet_module_stay`。
- 每个 session 内曝光只报一次，停留可以多段累计。

### 6.5 交互采集点

| 位置 | 现有函数/按钮 | 事件 |
| --- | --- | --- |
| 领养按钮 | `adoptPet()` | `pet_adopt_click` / `pet_adopt_success` |
| 打开全文 | `openContent()` | `content_open` |
| 内容消费服务端成功 | `submitContentEvent()` 成功返回 | `content_consume` / `content_interact` |
| 升级 | `data.reward.levelUp` 或服务端成长流水 | `pet_level_up` |
| 旅行开始 | `startTravel()` 成功 | `travel_start` |
| 旅行归来 | `completeTravel()` 成功 | `travel_complete` |
| 领取游历 | `claimTravel()` 成功 | `travel_claim` |
| 手账打开 | `openTravelHandbook()` | `handbook_open` |
| 排行榜打开 | `openLeaderboardPanel()` | `leaderboard_open` |
| 分享点击 | `publishLeaderboardShare()` 调接口前 | `pet_share_click` |
| 分享成功 | `publishLeaderboardShare()` 成功后 | `pet_share_success` |
| 新手引导展示 | `renderOnboardingGuide()` | `onboarding_step_show` |
| 新手引导完成 | `markOnboardingStep()` | `onboarding_step_done` |
| 新手引导跳过 | skip click | `onboarding_skip` |

## 7. 服务端补点方案

前端埋点适合记录曝光、停留、点击；服务端补点适合保证关键业务行为准确。

### 7.1 内容消费

在 `apply_content_event()` 成功写入 `pet_content_event` 后同步写：

- `content_consume`：`read/watch`
- `content_interact`：`like/comment/collect`
- 如发生升级，写 `pet_level_up`

### 7.2 游历

在以下服务端函数成功后补点：

- `start_travel()` -> `travel_start`
- `return_travel()` -> `travel_complete`
- `claim_travel()` -> `travel_claim`

### 7.3 分享

在 `/api/p1/community/leaderboard-share`：

- 进入接口即写 `pet_share_click` 可选，但建议前端写点击，服务端只写成功。
- 圈子发布成功且奖励发放成功后写 `pet_share_success`。
- 429 每日限制不算 success，可写 props `{ "blockedReason": "daily_limit" }` 到 `pet_share_click`。

### 7.4 统一写入函数

服务端新增：

    ...

并在函数内部同步 upsert `analytics_user_daily`。

## 8. 聚合口径

### 8.1 有效触达率

```text
有效触达率 = 当日 pet_module_expose 去重 UV / 当日 page_view('/') 去重 UV
```

### 8.2 平均模块停留

```text
平均停留时长 = 当日 pet_module_stay.duration_ms 总和 / 当日 pet_module_stay PV
```

### 8.3 30 秒跳出率

```text
30秒跳出率 = 当日 pet_module_stay duration_ms < 30000 的 UV / 当日 pet_module_expose UV
```

### 8.4 升级渗透率

```text
升级渗透率 = 当日至少 pet_level_up 1 次 UV / 当日 pet_module_expose UV
```

### 8.5 游历参与率

```text
游历参与率 = 当日 travel_start UV / 当日 pet_module_expose UV
```

### 8.6 分享成功率

```text
分享成功率 = 当日 pet_share_success UV / 当日 pet_share_click UV
```

### 8.7 分享回流

P1 支持：

- 分享链接带参数：`/?lks_share_user={userId}&lks_share_id={shareId}`。
- 首次曝光模块时读取参数上报 `pet_share_refer`。

| 场景 | 验收方式 |
| --- | --- |
| 首页访问 | `analytics_event` 有 `page_view` |

## 12. 风险与处理

- 前端埋点丢失：关键业务事件必须服务端补点。
- 重复上报：依赖 `event_id` 唯一约束去重。
- SQLite 写入压力：P0 数据量低，可同步写；如后续量大，改成本地队列或异步批处理。
- 停留时长不准：使用 `visibilitychange`、`pagehide`、路由切换多点兜底。
- 口径混乱：所有后台指标只从 `analytics_event` 和 `analytics_user_daily` 读取，`pet_*` 表只做业务事实补充。
