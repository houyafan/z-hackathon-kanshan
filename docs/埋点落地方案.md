# 看山陪伴计划｜轻量埋点落地方案

本文基于 `docs/埋点设计开发文档.md` 重新收敛为 P0 可快速落地版本：**去掉时长类埋点**，优先记录曝光、点击、成功、转化这类稳定行为结果，用更低成本支撑路演和产品验证。

## 1. 方案原则

### P0 做什么

- 记录用户是否看到、是否点击、是否完成关键行为。
- 支撑管理后台展示增长漏斗和趋势。
- 尽量复用现有业务事实表：`pet_content_event`、`pet_growth_log`、`pet_travel_event`、`project_daily_metric`。
- 关键业务行为由服务端补点，避免前端丢点影响核心数据。

### P0 不做什么

- 不记录页面停留时长。
- 不记录模块停留时长。
- 不记录页面离开事件。
- 不计算平均停留、跳出率。
- 不建设独立会话表。
- 不做复杂路径分析。

这样可以避开浏览器关闭、后台挂起、弹窗遮挡、滚动锁、`sendBeacon` 兼容等问题，让埋点先变成稳定的“行为漏斗”。

## 2. 当前状态

### 已具备

- 登录与用户体系：`zhihu_user` 已存在，线上通过 OAuth 内存会话获取可信 `user_id`，本地请求可使用 mock 用户预览。
- 每日注册登录：`project_daily_metric` 已记录每日注册用户数、登录次数，并在管理后台展示折线图。
- 内容消费：`pet_content_event` 已记录阅读、观看、点赞、评论、收藏等养成事件。
- 成长流水：`pet_growth_log` 已记录经验、等级、学识值、心情、游历精力等奖励与衰减。
- 游历记录：`pet_travel_event` 已支持游历开始、归来、领取。
- 排行榜与分享：已有等级榜、游历榜、发圈子奖励、每日分享频控。
- 新手引导：已有前端引导流程，但未落库。

### 当前缺口

- 缺少统一埋点事实表，无法记录曝光、按钮点击、弹窗打开、分享点击等非业务写库行为。
- 缺少用户日聚合，后台无法快速展示曝光、转化、分享等趋势。
- 新手引导、排行榜打开、分享点击等行为目前没有统一埋点。

## 5. 数据库模型

### 5.1 `analytics_event`

统一事件事实表，记录所有轻量行为埋点。

```sql
CREATE TABLE IF NOT EXISTS analytics_event (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  event_id TEXT NOT NULL,
  user_id INTEGER,
  visit_id TEXT,
  event_name TEXT NOT NULL,
  page_path TEXT,
  referer_path TEXT,
  target_type TEXT,
  target_id TEXT,
  props TEXT NOT NULL DEFAULT '{}',
  client_ts TEXT,
  server_ts TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,

  UNIQUE (event_id)
);

CREATE INDEX IF NOT EXISTS idx_analytics_event_user_time
  ON analytics_event (user_id, server_ts);

CREATE INDEX IF NOT EXISTS idx_analytics_event_visit_time
  ON analytics_event (visit_id, server_ts);

CREATE INDEX IF NOT EXISTS idx_analytics_event_name_time
  ON analytics_event (event_name, server_ts);

CREATE INDEX IF NOT EXISTS idx_analytics_event_page_time
  ON analytics_event (page_path, server_ts);
```

说明：

- `visit_id` 只用于串联同一次前端访问，不做访问时长统计。
- `props` 存 JSON，承载等级、内容类型、按钮位置、来源等扩展字段。
- `event_id` 做去重，前端与服务端都必须生成。

### 5.2 `analytics_user_daily`

用户日聚合表，写事件时同步 upsert，用于管理后台快速查询。

```sql
CREATE TABLE IF NOT EXISTS analytics_user_daily (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL,
  stat_date TEXT NOT NULL,
  page_view_count INTEGER NOT NULL DEFAULT 0,
  pet_module_expose_count INTEGER NOT NULL DEFAULT 0,
  pet_adopt_click_count INTEGER NOT NULL DEFAULT 0,
  pet_adopt_success_count INTEGER NOT NULL DEFAULT 0,
  content_open_count INTEGER NOT NULL DEFAULT 0,
  read_count INTEGER NOT NULL DEFAULT 0,
  watch_count INTEGER NOT NULL DEFAULT 0,
  like_count INTEGER NOT NULL DEFAULT 0,
  comment_count INTEGER NOT NULL DEFAULT 0,
  collect_count INTEGER NOT NULL DEFAULT 0,
  level_up_count INTEGER NOT NULL DEFAULT 0,
  travel_start_count INTEGER NOT NULL DEFAULT 0,
  travel_complete_count INTEGER NOT NULL DEFAULT 0,
  travel_claim_count INTEGER NOT NULL DEFAULT 0,
  handbook_open_count INTEGER NOT NULL DEFAULT 0,
  leaderboard_open_count INTEGER NOT NULL DEFAULT 0,
  share_click_count INTEGER NOT NULL DEFAULT 0,
  share_success_count INTEGER NOT NULL DEFAULT 0,
  share_refer_count INTEGER NOT NULL DEFAULT 0,
  onboarding_show_count INTEGER NOT NULL DEFAULT 0,
  onboarding_done_count INTEGER NOT NULL DEFAULT 0,
  onboarding_skip_count INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,

  UNIQUE (user_id, stat_date)
);

CREATE INDEX IF NOT EXISTS idx_analytics_user_daily_date
  ON analytics_user_daily (stat_date);
```

## 6. 上报接口

### 6.1 批量上报

```http
POST /api/analytics/events
Content-Type: application/json

{
  "visitId": "lks_visit_...",
  "events": [
    {
      "eventId": "evt_...",
      "eventName": "pet_module_expose",
      "pagePath": "/",
      "refererPath": "/people/p2wcex",
      "targetType": "pet",
      "targetId": "liukanshan",
      "clientTs": "2026-05-11T00:00:00.000Z",
      "props": {
        "petLevel": 4,
        "isNewUser": false,
        "deviceType": "desktop"
      }
    }
  ]
}
```

返回：

```json
{
  "ok": true,
  "accepted": 1,
  "duplicated": 0
}
```

### 6.2 服务端写点函数

新增统一函数：

```python
def record_analytics_event(
    conn,
    event_name,
    user_id=None,
    visit_id=None,
    event_id=None,
    page_path=None,
    referer_path=None,
    target_type=None,
    target_id=None,
    props=None,
    client_ts=None,
):
    ...
```

函数职责：

- 生成缺省 `event_id`。
- 写入 `analytics_event`。
- 对重复 `event_id` 做幂等忽略。
- 同步更新 `analytics_user_daily`。

## 7. 前端采集方案

### 7.1 轻量 visit id

- 使用 `sessionStorage.liukanshan_analytics_visit_id`。
- 刷新页面保留，新标签页重新生成。
- 只用于串联事件，不计算访问时长。

### 7.2 上报策略

- 事件进入内存队列。
- 每 3 秒或累计 10 条批量上报。
- 页面关键点击事件可以立即 flush。
- 不依赖 `pagehide` 或 `beforeunload` 做核心统计。
- 上报失败不影响业务流程。

### 7.3 前端采集点

| 位置 | 现有函数/按钮 | 事件 |
| --- | --- | --- |
| 路由渲染完成 | `renderCurrentRoute()` | `page_view` |
| 看山信息卡曝光 | `[data-pet-panel]` + `IntersectionObserver` | `pet_module_expose` |
| 点击领养 | `[data-adopt]` | `pet_adopt_click` |
| 打开全文 | `openContent()` | `content_open` |
| 打开旅行手账 | `openTravelHandbook()` | `handbook_open` |
| 打开排行榜 | `openLeaderboardPanel()` | `leaderboard_open` |
| 点击分享奖励 | `publishLeaderboardShare()` 调接口前 | `pet_share_click` |
| 新手引导展示 | `renderOnboardingGuide()` | `onboarding_step_show` |
| 新手引导完成 | `markOnboardingStep()` | `onboarding_step_done` |
| 跳过新手引导 | skip click | `onboarding_skip` |

### 7.4 曝光去重

- `pet_module_expose` 每个 `visit_id` 内只上报一次。
- 通过 `IntersectionObserver` 判断进入视口，阈值建议 `0.5`。
- 如果页面布局导致右侧卡默认可见，渲染后下一帧即可检查。

## 8. 服务端补点方案

前端记录曝光、打开、点击；服务端记录真正成功的业务结果。

### 8.1 领养

领养成功后写：

- `pet_adopt_success`

props：

```json
{
  "petLevel": 1,
  "source": "profile_panel"
}
```

### 8.2 内容消费与互动

在 `apply_content_event()` 成功写入 `pet_content_event` 后写：

- `content_consume`：`read/watch`
- `content_interact`：`like/comment/collect`
- `pet_level_up`：如果本次事件触发升级

props 示例：

```json
{
  "contentId": "content_001",
  "contentType": "article",
  "actionType": "read",
  "petLevel": 4,
  "levelUp": false
}
```

重复内容、重复点赞等不再写成功类埋点，可在前端提示即可。

### 8.3 游历

成功后补点：

- `start_travel()` -> `travel_start`
- `return_travel()` -> `travel_complete`
- `claim_travel()` -> `travel_claim`

props：

```json
{
  "travelId": "travel_xxx",
  "theme": "hotspot",
  "petLevel": 4
}
```

### 8.4 分享发圈

在 `/api/p1/community/leaderboard-share`：

- 前端点击按钮写 `pet_share_click`。
- 圈子发布成功且奖励发放成功后，服务端写 `pet_share_success`。
- 每日频控 429 不算成功，但前端 `pet_share_click` 仍保留。

props：

```json
{
  "shareType": "level_card",
  "channel": "community",
  "ringName": "黑客松脑洞补给站",
  "petLevel": 4
}
```

### 8.5 分享回流

P1 或 P0 后半段实现：

- 分享链接增加参数：`/?lks_share_user={userId}&lks_share_id={shareId}`。
- 新用户或老用户通过链接进入首页并曝光看山模块后，上报 `pet_share_refer`。

## 10. 开发拆解

### 阶段 1：数据库与服务端基础

1. 在 `db/sqlite/init_p0.sql` 新增 `analytics_event`、`analytics_user_daily`。
2. 在 `p0_mock/server.py` 增加 migration。
3. 新增 `record_analytics_event()`。
4. 新增 `upsert_analytics_user_daily()`。
5. 新增 `POST /api/analytics/events`。

### 阶段 2：服务端关键补点

1. 领养成功补 `pet_adopt_success`。
2. 内容消费成功补 `content_consume` / `content_interact`。
3. 升级成功补 `pet_level_up`。
4. 游历开始、归来、领取分别补点。
5. 分享成功补 `pet_share_success`。

### 阶段 3：前端轻量采集

1. 新增 visit id 与事件队列。
2. 接入 `page_view`。
3. 接入 `pet_module_expose`。
4. 接入领养点击、排行榜打开、手账打开、分享点击。
5. 接入新手引导展示、完成、跳过。

### 阶段 4：管理后台

1. 扩展 `admin_overview_payload()` 返回 analytics 今日指标。
2. 新增 14 天趋势数据。
3. 前端管理后台增加指标卡、趋势图、漏斗。

### 阶段 5：分享回流

1. 分享链接追加 `lks_share_user`、`lks_share_id`。
2. 首页读取分享参数。
3. 看山模块曝光后上报 `pet_share_refer`。
4. 后台展示分享回流 UV。

## 11. 验收标准

| 场景 | 验收方式 |
| --- | --- |
| 首页访问 | `analytics_event` 有 `page_view` |
| 看山模块曝光 | 首页右侧卡进入视口后有 `pet_module_expose` |
| 领养 | 点击有 `pet_adopt_click`，成功有 `pet_adopt_success` |
| 内容打开 | 打开全文后有 `content_open` |
| 内容养成 | 阅读、点赞、评论、收藏成功后有对应消费/互动事件 |
| 升级 | 等级变化后有 `pet_level_up` |
| 游历 | 开始、归来、领取分别有事件 |
| 排行榜 | 打开弹窗有 `leaderboard_open` |
| 分享 | 点击有 `pet_share_click`，成功发圈有 `pet_share_success` |
| 后台 | 管理后台能看到曝光、消费、升级、游历、分享趋势 |

## 12. 风险与处理

- 前端埋点丢失：关键业务结果由服务端补点。
- 重复上报：依赖 `event_id` 唯一约束去重。
- SQLite 写入压力：P0 数据量低，可同步写；后续量大再做批处理。
- 口径混乱：后台 P0 指标只读 `analytics_event` 和 `analytics_user_daily`，业务表只作为补点来源。
- 分享回流参数被复制丢失：P0 先只统计带参数访问，后续再补短链或服务端跳转。
