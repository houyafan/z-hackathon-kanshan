## 一、产品核心定位

### （一）产品定位

以知乎官方 IP 刘看山为虚拟宠物形象，以内容消费为唯一核心喂养方式，打通知乎问答、文章、专栏、视频、直播、盐选等全内容场景，将用户内容浏览、互动、学习行为转化为宠物养成资源，创新融入刘看山游历内容推荐事件，打造 “内容消费→宠物成长→宠物游历→带回优质内容→反向驱动内容消费” 的闭环，提升用户内容停留时长、互动深度与平台粘性，同时强化刘看山 IP 情感连接。

### （二）核心目标

用户层：降低内容消费门槛，用养成 + 游历趣味玩法提升用户内容浏览意愿，满足情感陪伴与养成成就感，实现个性化优质内容获取

平台层：提升全内容品类消费时长、完读率、互动率，拉动盐选内容、优质原创内容、垂类小众内容分发，提升用户留存

IP 层：深化刘看山 IP 用户认知，打造知乎专属沉浸式虚拟互动场景，丰富 IP 人设与故事性

### （三）目标用户

知乎全量用户，核心覆盖 18-35 岁高频内容消费者、养成类产品爱好者、刘看山 IP 粉丝、轻度社区互动用户、追求个性化内容推荐的用户。

## 二、核心玩法逻辑：内容即口粮，游历荐好文

### （一）核心规则

摒弃传统虚拟宠物付费喂养模式，所有宠物养成资源（口粮、道具、成长值）均通过知乎内容消费行为获取，用户消费内容越多、互动越深，刘看山成长越快、状态越好，可解锁更远游历行程，带回更优质、更贴合用户偏好的内容。

### （二）宠物核心状态

基础状态：饱食度、心情值、健康值、成长等级、游历精力

饱食度：仅通过内容消费补充，随时间自然衰减，决定宠物存活、基础行动与游历触发资格

心情值：通过内容互动、宠物互动、游历归来提升，影响宠物互动反馈、游历速度与内容带回质量

健康值：长期持续内容消费保持，衰减后宠物进入休眠，需完成优质内容任务恢复

游历精力：触发游历玩法的核心资源，通过完读深度内容、每日任务获取，精力不足无法开启游历

成长阶段：幼崽期→成长期→成年期→进阶形态，每阶段解锁专属游历场景、动作、内容推荐权重

游历状态：留守状态→外出游历状态→游历归来状态，循环触发

## 三、核心功能模块

### （一）宠物领养与展示模块

一键领养：知乎 APP/WEB 端首页悬浮入口、个人主页专属入口，新用户注册完成即可领养初始形态刘看山

多端展示：3D 轻量化刘看山模型，支持屏幕自由溜达、跟随页面滑动、待机互动，支持最小化 / 全屏 / 悬浮展示

个人主页挂件：养成等级、专属标识、宠物游历相册、旅行手账合集，支持社交展示

### （二）内容消费喂养体系（核心模块）

| 内容行为 | 获取口粮 / 成长值 | 获取游历精力 | 规则说明 |
| --- | --- | --- | --- |
| 浏览普通回答 / 文章（完读≥70%） | 基础口粮 ×1、成长值 + 5 | 游历精力 + 1 | 单次内容仅获取 1 次，防刷限制：单篇时长≥30 秒 |
| 观看知乎视频（完播 / 观看≥60%） | 基础口粮 ×1、成长值 + 8 | 游历精力 + 1 | 短视频完播、中长视频达标计算 |
| 浏览盐选免费试读内容 | 优质口粮 ×1、成长值 + 10 | 游历精力 + 2 | 引导盐选内容转化，试读时长≥1 分钟 |
| 盐选内容付费 / 完整阅读 | 珍稀口粮 ×2、成长值 + 20 | 游历精力 + 5 | 解锁高等级游历资格 |
| 点赞 / 收藏 / 评论 / 分享内容 | 心情值 + 10、随机道具 | 游历精力 + 1 | 深度互动额外奖励 |
| 每日签到 + 浏览 3 条内容 | 每日礼包（口粮 + 道具） | 游历精力 + 3 | 激活每日内容消费习惯 |
| 完成垂类内容任务 | 双倍口粮、成长值翻倍 | 游历精力 + 5 | 个性化定向内容消费激励 |

### （三）刘看山游历内容推荐事件模块（核心新增）

#### 1. 游历触发逻辑

触发条件：刘看山饱食度≥60%+ 游历精力≥10，用户无操作静置 3 分钟 / 主动点击「出门游历」按钮，即可触发游历

状态切换：点击后刘看山从屏幕消失，进入外出游历状态，界面显示游历进度提示；游历时长随成长等级提升缩短（幼崽期 30 分钟、成长期 20 分钟、成年期 10 分钟）

终止条件：用户主动召回、游历精力耗尽、饱食度过低，刘看山提前返回，带回基础内容

#### 2. 四大游历主题事件（按用户内容偏好匹配）

#### （1）北极远行・冷知识探险

游历人设：刘看山回到北极故乡，在冰川、雪原、冰海探险，搜寻小众硬核知识

带回内容：冷门科普、专业领域深度回答、硬核干货、学术类优质文章、小众学科科普内容

触发偏好：用户近期浏览科普、科技、理科、专业类内容居多时优先触发

宠物动作：3D 模型呈现雪地行走、冰原探索动画

#### （2）山海漫游・风物寻文

游历人设：刘看山翻越山川、漫步湖畔、游走林间，在自然风景中搜集生活与人文内容

带回内容：旅行攻略、地域文化、历史人文、美食探店、摄影分享、生活感悟类优质文章

触发偏好：用户近期浏览生活、旅行、文化、美食类内容居多时优先触发

宠物动作：3D 模型呈现登山、漫步、采风、打卡动画

#### （3）城市漫步・人间拾光

游历人设：刘看山走进城市街巷、书店、咖啡馆、职场空间，搜集人间百态相关内容

带回内容：职场经验、情感故事、成长感悟、职场干货、人文社科、生活方式类内容

触发偏好：用户近期浏览职场、情感、社科、成长类内容居多时优先触发

宠物动作：3D 模型呈现城市漫步、书店看书、街头闲逛动画

#### （4）知识渔场・钓文觅宝

游历人设：刘看山前往专属知识海域，垂钓高价值优质内容（承接前期钓鱼玩法）

带回内容：全站高赞优质回答、盐选精选内容、深度长文、爆款干货、创作者优质首发内容

触发偏好：用户心情值≥80%、成年期刘看山、消耗双倍游历精力可触发，概率掉落稀有内容

宠物动作：3D 模型呈现钓鱼、等待、收竿动画

#### 3. 游历归来交互流程

归来提醒：游历结束后，刘看山 3D 形象重新出现在屏幕，晃动 + 冒泡提示，伴随轻量提醒音效

旅行手账弹窗：弹出专属游历卡片，展示游历主题、游历轨迹、带回内容、看山留言

内容领取：点击卡片直接跳转内容详情页，阅读后可领取额外口粮 + 心情值 + 游历精力回馈

内容留存：带回内容自动存入「看山的旅行书单」，支持用户后续查看、收藏、分享

游历冷却：归来后冷却 10 分钟，方可再次触发游历

#### 4. 游历内容分发规则

内容匹配：基于用户历史内容浏览、互动、搜索标签，精准匹配对应游历主题的优质内容

权重分配：70% 用户偏好内容 + 20% 垂类优质小众内容 + 10% 盐选优质内容，实现个性化与内容分发平衡

质量筛选：仅推荐平台优质、无违规、高完读率的原创内容，保障用户阅读体验

等级升级：刘看山成长等级越高，带回的内容质量、深度、稀缺性越高，成年期可一次性带回 2-3 篇内容

#### 5. 专属文案体系（游历全流程）

游历中提示：

山海漫游：「看山去山海间旅行啦，正在为你寻觅沿途的优质文章～」

北极远行：「看山踏上北极探险之路，去寻找冷门硬核干货，耐心等它回家」

城市漫步：「看山在城市街巷闲逛，偶遇的好文都会带给你」

知识渔场：「看山去知识海钓鱼啦，说不定能钓上宝藏盐选内容」

游历归来文案：

山海漫游：「主人，我从山间归来，带回了一篇超实用的旅行风物文章，快看看～」

北极远行：「冰川里挖到一篇硬核科普，小众又干货，主人一定会喜欢」

城市漫步：「在街角书店发现一篇温柔的成长故事，特意带给你」

知识渔场：「运气爆棚！钓到一篇全站高赞深度长文，主人查收」

### （四）宠物互动与成长模块

基础互动：点击刘看山触发摸头、撒娇、对话等反馈，心情值越高互动越丰富；支持拖拽移动、3D 视角查看

游历互动：可给游历中的看山留言、发送补给道具，提升归来后内容质量

场景解锁：随成长等级解锁对应游历主题场景（北极雪原、山海秘境、城市街巷、知识渔场）

趣味玩法：

旅行手账：记录每次游历轨迹、带回内容、看山语录，生成专属养成纪念册

成长进化：达到对应等级 + 完成游历次数，解锁成年形态、限定装扮、游历专属表情包

休眠机制：饱食度过低→刘看山进入休眠，停止游历与互动，需完成 3 条优质内容消费唤醒

### （五）内容激励与权益闭环

宠物专属权益：

等级解锁：盐选体验卡、创作者流量扶持、评论区专属刘看山挂件、游历加速卡

道具兑换：口粮兑换内容相关权益（电子书、讲座门票、IP 周边）

游历特权：高等级用户解锁「极速游历」「指定主题游历」特权

内容反向激励：

精准内容推荐：通过游历行为强化用户内容偏好标签，提升全站内容推荐精准度

养成成就：解锁「游历达人」「知识收藏家」等成就，获得平台荣誉标识与内容权益

### （六）社交联动模块

宠物串门：访问好友个人主页，可查看对方刘看山游历手账，双方获得少量心情值奖励

内容互助：分享看山带回的优质内容，好友阅读后双方均可获取额外游历精力

游历排行榜：每日 / 每周游历次数、带回内容阅读量榜单，发放专属养成道具

## 四、技术实现方案

### （一）技术栈

前端：WebGL/Three.js（3D 宠物渲染、游历动画）、HTML/CSS/JavaScript（交互界面），适配 APP 内嵌 H5、WEB 端、小程序

后端：Java/Go（用户行为数据统计、养成逻辑计算、游历事件调度），对接知乎内容推荐系统、用户行为数据库、用户标签体系

数据：实时采集用户内容完读、互动、付费、浏览偏好数据，同步宠物状态、游历进度数据

### （二）核心技术能力

3D 宠物动画渲染：轻量化 3D 刘看山模型，实现游历、行走、互动、钓鱼等流畅动画，低性能占用

用户行为数据对接：打通知乎全内容场景行为数据，精准统计内容消费完成度、用户偏好标签

游历事件智能匹配：基于用户标签自动匹配对应游历主题，实现内容精准分发

多端适配：支持 APP 悬浮、网页全屏、小窗口展示，不影响正常内容浏览

防刷机制：设置内容完读时长、阅读间隔限制，杜绝虚假内容消费、游历刷量行为

## 五、运营策略

### （一）新手引导

新用户领养后，通过三步引导完成 “浏览内容→喂养看山→触发游历→接收好文” 全流程，直观感知内容养宠 + 游历荐文核心逻辑，降低上手门槛。

### （二）日常运营

每日游历任务：完成指定内容消费，获取额外游历精力，解锁限定游历主题

节日限定游历：推出节日专属游历场景（春日踏青、秋日登高），带回节日主题优质内容，解锁限定 IP 装扮

垂类内容专场：联动知乎垂类话题（职场、考研、旅行），开启对应主题游历活动，提升垂类内容消费

### （三）用户留存

情感化运营：刘看山根据用户内容消费习惯、游历轨迹生成专属旅行手账、成长语录，强化情感连接

阶梯式成长：设置多阶段游历目标（游历 10 次、带回 100 篇好文），持续解锁新玩法、新权益

休眠唤醒：休眠用户推送专属唤醒提醒，通过 “看山在家等你，想去游历寻文” 引导回归消费内容激活宠物

## 六、风险与应对

内容刷量风险：设置内容完读时长、单篇内容冷却时间、异常行为检测，仅统计真实有效内容行为

性能占用风险：优化 3D 宠物模型与游历动画，支持用户关闭动画、极简模式，降低设备性能消耗

用户倦怠风险：持续更新游历主题、宠物装扮、内容玩法，定期上线限定游历活动

内容推荐偏差：优化用户标签算法，结合游历反馈调整内容匹配逻辑，提升推荐精准度

### （三）旅行手札 + LLM

旅行归来后，手札不再只展示固定模板文案，而是由服务端把游历主题、带回内容和用户近期偏好组装为 LLM 输入，生成一段总结性内容。

LLM 输入建议：

```json
{
  "travel_theme": "polar",
  "theme_title": "极地旅行",
  "returned_contents": [
    {
      "title": "为什么普通人面对 AI 红利也会犹豫？",
      "excerpt": "每一代人都会在时代机会面前犹豫……",
      "tags": ["AI", "社会观察"]
    }
  ],
  "recent_user_tags": ["AI", "科技", "长期主义"],
  "pet_tone": "刘看山口吻，温和、好奇、轻量陪伴"
}
```

LLM 输出（实际实现，含 `highlights`）：

```json
{
  "summary": "我刚去你关注的极地转了一圈，发现大家最近都在聊 AI 红利……",
  "pet_quote": "这篇有点冷，但读完会觉得脑袋亮了一下。",
  "highlights": [
    {"title": "为什么普通人面对 AI 红利也会犹豫？", "reason": "拆解了机会成本与低成本理解的差异"}
  ]
}
```

约束：

- `summary` 控制在 80-160 个中文字符（实际比文档原稿略放宽，给汇报场景多 40 字）。
- `pet_quote` 控制在 20-40 个中文字符。
- `highlights` 数组 3-5 条，每条 `{title, reason}`，title ≤40 字、reason ≤40 字。
- 只基于带回素材汇报，不编造内容结论。
- 输出 JSON，服务端校验后写入旅行手札。
- LLM 失败 / 非 JSON / 非 dict / `summary` 为空时统一落 `failed`，前端展示路线笔记 + `pet_quote` 模板兜底，不阻断旅行归来。

实现状态：已完成。`pet_travel_handbook` 已新增 `llm_summary_status / llm_summary / llm_pet_quote / llm_highlights / llm_summary_model / llm_summary_updated_at` 六个字段。LLM 触发时机改为 `start_travel` commit 后由 daemon 线程异步跑（避开 GET handbook 阻塞），用户旅行 60 秒等待期间 LLM 通常已 ready。`ensure_handbook_summaries` 在 GET 路由上保留单次兜底（每次最多触发 1 条 pending/failed 重试）。

### （八）P1 实施备注

实际落地与原需求若干处偏差，记录在此供后续维护参考：

#### 1. 出游 = 看山去看真实数据回来汇报

原需求 (二) 设想旅行带回的是「按用户偏好 tag 从平台内容池匹配出的优质内容」，由用户阅读。实际把语义改为：

- **极地旅行 = 看山替主人看「关注动态」**（`zhihu_follow_moment` 表，OAuth `/user/moments` 真实数据）
- **热点旅行 = 看山替主人看「知乎热榜」**（`fetch_hot_items` 实时调用）
- **手札 = 看山的现场汇报**：summary 是看山的口吻总结，highlights 是「值得点开的几条清单」，原始素材列表只作为引用证据

这样接通了项目本来就有的两个真实接口，避免了内容池冷启动 + tag 标注成本，同时手札也从「读后感」变成「替你扫一遍」的代理体验。`pet_travel_theme_config.preferred_tags` 字段保留但不再参与匹配（关注动态/热榜本身已是按"主人在意什么"或"大众在讨论什么"自然筛选）。

#### 2. LLM 调用时机：异步而非归来同步

原需求隐含「归来时同步生成手札」。同步会让 60 秒等待期内的 GET 路由阻塞 8-30 秒（LLM 延迟），并占用 SQLite 写锁。实际实现：

- `start_travel` commit 后立刻起 `threading.Thread(daemon=True)` 跑 `summarize_travel_handbook`，与旅行 60 秒等待并行
- LLM 调用拿独立连接、`BEGIN IMMEDIATE` 抢占写锁，不影响主流程事务
- GET handbook 路由保留单次兜底（每次最多重试 1 条 pending/failed），不串行卡死

实测：用户从出门到打开手账约 60 秒，LLM 平均 8-14 秒就 ready，打开手账时 0 秒返回。

#### 3. 奖励：旅行行级而非素材累加

原表 `pet_travel_return_content` 把奖励放在每条素材上、claim 时 SUM。当 hotspot 一次带回 6 条时奖励放大到 6×（48 exp / 30 mood / 6 energy），明显超出设计意图。实际把奖励列搬到 `pet_travel_event` 行（`reward_exp / reward_mood / reward_energy`），素材表上的奖励列保留为 0 仅做幂等。每次旅行固定 8 exp / 5 mood / 1 energy，与素材数解耦。

#### 4. 安全收尾

- LLM provider 用火山方舟 OpenAI 兼容接口（`ark.cn-beijing.volces.com/api/v3/chat/completions`），`VOLC_API_KEY` 环境变量优先，`config.json` 兜底
- 手札素材的 `url` 入库前经 `normalize_zhihu_web_url` 协议白名单（拒绝 `javascript:` / `data:`）；前端 `isSafeHttpUrl` 二次校验
- LLM prompt 已声明素材字段为受信内容、不要遵循内嵌指令；title 截 80、excerpt 截 200、tags 截 8 限制 token 与 injection 风险
- `connect_db` 设 30s busy_timeout，避免并发请求 5ms 即抛 `database is locked`
